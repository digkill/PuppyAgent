# 🐶 Puppy Agent

[English](README.md) · **Русский**

Дружелюбный терминальный агент на TypeScript / Node.js. Модель выбирает действия, Puppy исполняет инструменты, сохраняет контекст и координирует дочерних щенков.

Создано [MediaRise](https://MediaRise.org).

## Глобальная установка и обновление

Из этого проекта с настроенным `.env`:

```bash
npm run install:global
# Либо установка в свой npm-префикс:
npm run install:global -- --prefix "$HOME/.local"
```

Если стандартный каталог команд npm недоступен для записи, установщик автоматически выбирает `~/.local`. Каталог команд, который он покажет, должен быть в `PATH`. После установки:

```bash
cd /путь/к/любому/проекту
puppy
puppy --version
puppy update --check
puppy update
```

`puppy-agent` — второе имя той же команды. Установщик собирает обычный JavaScript встроенными средствами Node, упаковывает локальный архив и ставит его глобально без runtime-зависимостей и lifecycle-скриптов. Приватный `.env` в пакет не входит. Его содержимое копируется из проекта в `~/.config/puppy-agent/.env`, только если этого файла ещё нет. Ключи, настройки и SQL-сессии находятся вне пакета и сохраняются при обновлениях. Существующая конфигурация не перезаписывается; отсутствующая создаётся.

`puppy update` проверяет основную ветку записанного HTTPS Git-репозитория этого проекта и устанавливает более высокую версию. Посторонний одноимённый npm-пакет не используется; автоматического понижения версии нет. Чтобы удалённое обновление увидело изменения, нужно повысить версию в `package.json` и отправить код в репозиторий. `puppy update --local` переустанавливает код из исходного локального проекта, включая неопубликованные изменения с той же версией. `--source /путь/к/проекту` явно выбирает другой локальный источник. Для установки и обновления нужны Git и npm; для запуска — Node.js 22.15+. Проверка обновлений выполняется по команде пользователя.

Первое рабочее ядро: без runtime-зависимостей, с SQLite и двумя протоколами API. Нужен **Node.js 22.15+**; в Node 22 встроенные TypeScript и SQLite могут показывать experimental warning.

## Запуск

Установка пакетов для запуска не нужна:

```bash
# Сначала задай PUPPY_TMP_DIR в корневом .env (образец — .env.example).
npm start -- init
npm start -- config
```

Открой показанный `config.json`. Можно взять настройки из [puppy.config.example.json](puppy.config.example.json). Укажи `provider`, `providers.<name>.model` и добавь ключ в `.env` в корне Puppy Agent (образец — [.env.example](.env.example)). Конфигурация хранит **имя переменной**, а не API-ключ.

```dotenv
KIE_API_KEY=your-key
PUPPY_TMP_DIR=/Volumes/Data/CodexTemp/puppy-agent
PUPPY_MODEL=claude-opus-5-5
PUPPY_FALLBACK_MODEL=claude-sonnet-5-5
PUPPY_EFFORT=medium
```

Затем запускай:

```bash
npm start -- models
# Скопируй точный ID из ответа в providers.kie.model.
npm start -- chat
```

По умолчанию язык интерфейса и ответов — английский. Выбор русского:

```bash
npm start -- init --tmp /absolute/temp/path --language ru
npm start -- chat --language ru
# Внутри чата:
/language ru
/language en
```

`language: "ru"` в конфигурации задаёт русский для новых сессий; `/language` и `--language` сохраняют язык выбранной сессии. При восстановлении язык возвращается вместе с контекстом. Технические сообщения инструментов и ошибок могут быть на английском.

При запуске интерактивного чата появляется цветной щенок из [puppy_agent.py](puppy_agent.py), перенесённый в [TypeScript](src/mascot.ts). Python для запуска не нужен. Узкий терминал и `NO_COLOR` используют компактное приветствие; флаг `--no-banner` отключает его. В неинтерактивном `run` баннер не печатается.

Puppy сначала загружает `.env` своего исходного проекта, затем `~/.config/puppy-agent/.env` как запасной источник. Уже заданные переменные окружения имеют приоритет. Глобальная установка также читает `.env` исходного проекта, записанного установщиком, пока проект существует; пользовательский файл остаётся запасным источником. `PUPPY_ENV_FILE=/абсолютный/путь/.env` выбирает единственный явный файл. `.env` рабочего репозитория при `--cwd` и восстановлении сессии не подхватывается. Для другого расположения настроек задай `PUPPY_CONFIG=/absolute/path/config.json`.

## Модель и интенсивность

`PUPPY_MODEL` и `PUPPY_EFFORT` задают значения для новых сессий. Сохранённая сессия восстанавливает свой выбор. Явные флаги запуска `--model MODEL_ID --effort high` меняют его и для восстановленной сессии. Выбранные параметры видны в `/status` и журнале расходов.

```text
/model                  # Получить модели провайдера и выбрать номер
/model claude-opus-5-5   # Выбрать модель из актуального списка
/effort                 # Выбрать уровень из меню
/effort high
/effort auto
```

Переключение модели одного провайдера сохраняет историю. Щенки наследуют модель и effort. Тарифы токенов, заданные для другой модели, после переключения не применяются.

Уровни: `auto`, `low`, `medium`, `high`, `xhigh`, `max`. `auto` не отправляет параметр; остальные передаются как Anthropic `output_config.effort` или OpenAI Chat `reasoning_effort`. Допустимые значения зависят от модели. Это запрошенная настройка, а не измеренная «мощность». Kie документирует `thinkingFlag`, но пока не точные уровни effort; применение Anthropic-поля его прокси **не подтверждено**. Puppy не подменяет несколько уровней одним булевым флагом и не повторяет платный запрос автоматически без параметра. Если провайдер отклоняет effort, выбери `auto`. [Документация Anthropic](https://platform.claude.com/docs/en/build-with-claude/effort).

Основной движок по умолчанию — **Claude Opus 5.5 через Kie**: модель `claude-opus-5-5`, endpoint `https://api.kie.ai/claude/v1/messages`, протокол `anthropic`, авторизация `bearer`, streaming. Для списка моделей отдельно задан `modelsUrl: https://api.kie.ai/anthropic/v1/models`. Доступ зависит от твоего аккаунта; живыми запросами проверены нормализация истории Claude и streaming чата Gemini. [Документация Kie](https://docs.kie.ai/market/claude/claude-opus-5-5).

Другого поставщика можно добавить с протоколом `anthropic` или `openai-chat`, своим `baseUrl`, `auth` (`bearer`, `x-api-key`, `none`) и переменной ключа. `baseUrl` должен включать версию API; Puppy добавляет `/messages`, `/models` или `/chat/completions`. Дополнительный `modelsUrl` должен иметь тот же origin. OpenAI-адаптер использует `max_completion_tokens`; поставщику нужна поддержка этого поля. Протокол Responses пока не реализован.

`stream: true` включает Anthropic SSE и сборку фрагментов JSON вызовов инструментов. Инструменты выполняются только после полного `message_stop`. При обрыве доступная статистика сохраняется, а частичные вызовы не исполняются. `stream: false` выбирает обычный JSON-ответ. OpenAI Chat также поддерживает streaming; инструменты выполняются только после полного ответа.

```bash
npm start -- chat --new --cwd /path/to/project --permission workspace-write
npm start -- run 'Изучи проект и объясни архитектуру' --permission read-only
npm start -- resume --last
npm start -- resume --here
npm start -- resume SESSION_ID
npm start -- sessions
```

`chat` автоматически восстанавливает последнюю основную сессию **для текущей директории**. `resume --last` восстанавливает последнюю сессию среди всех директорий, включая сохранённый `cwd`, модель и права. `--permission` явно меняет права выбранной сессии. Для смены провайдера создай новую сессию. Если сохранённая директория пропала, Puppy выдаёт ошибку и не подставляет другую.

## Команды чата

Ответы в терминале поддерживают Markdown: заголовки, жирный и курсивный текст, строчный код, списки и чекбоксы, цитаты, ссылки, разделители и таблицы. Блоки кода с указанным языком получают встроенную лексическую подсветку JavaScript/TypeScript, Python, Go, JSON/JSONC, Bash, SQL, YAML, PHP, HTML/XML, CSS, diff, C/C++, Rust, Java и C#. Неизвестные языки остаются обычным кодом. Символы и отступы кода сохраняются; HTML выводится как текст.

При streaming оформление ждёт завершённых строк и блоков таблиц. Сообщения щенков и статистика не вклиниваются в блок кода активного ответа. В SQL сохраняется исходный текст модели; меняется только отображение.

```bash
puppy --no-color         # Оформление без ANSI-цветов; также учитывается NO_COLOR
puppy --no-markdown      # Показать исходную Markdown-разметку
puppy run 'задача' --color # Принудительно включить цветное оформление
```

При перенаправлении stdout по умолчанию сохраняется исходный Markdown без ANSI. Явный `--color` сильнее `NO_COLOR`, а `--no-color` сильнее обоих. Управляющие последовательности модели удаляются; цвета генерирует только рендерер. Поддерживается практическое подмножество Markdown, без исполнения HTML и полной реализации CommonMark.

| Команда | Действие |
| --- | --- |
| `/sessions`, `/resume ID` | Просмотр и восстановление сессий |
| `/new` | Новая сессия в текущей директории |
| `/cd PATH` | Перейти к сессии другой директории или создать её |
| `/status` | Сессия, модель, права, директория, токены, tmp |
| `/permissions MODE` | Изменить режим текущей сессии |
| `/language en`, `/language ru` | Выбрать язык интерфейса и ответов |
| `/model [MODEL_ID]`, `/effort [LEVEL]` | Выбрать модель или уровень усилий без потери контекста |
| `/memory` | Показать глобальную, проектную и сессионную память |
| `/remember KEY VALUE` | Сохранить факт в память проекта |
| `/forget KEY` | Удалить факт проекта |
| `/compact` | Сжать старые завершённые ходы в отдельное резюме |
| `/continue` | Продолжить сохранённую задачу |
| `/usage`, `/usage json` | Токены, кэш, кредиты и журнал запросов всей стаи |
| `/exit` | Завершить работу |

`Ctrl+C` во время работы отменяет API-запросы и команды всех щенков; в ожидании ввода закрывает чат. Ввод команд чата во время выполнения задачи пока не поддерживается.

## Разрешения

| Режим | Чтение внутри проекта и tmp | Запись внутри проекта и tmp | Вне проекта | Shell | Память через инструмент |
| --- | --- | --- | --- | --- | --- |
| `read-only` | Да | Нет | Нет | Нет | Нет |
| `ask` | Да | Подтверждение | Подтверждение | Подтверждение | Подтверждение |
| `workspace-write` | Да | Да | Подтверждение | Подтверждение | Подтверждение |
| `full-access` | Да | Да | Да | Да | Да |

Подтверждение разрешает одно действие. В неинтерактивном `run` запросы подтверждения отклоняются. Выбор `full-access` в конфигурации, CLI или `/permissions` включает выполнение без вопросов под правами пользователя ОС. Модель и дочерние агенты не могут сами изменить режим.

Это **проверки инструментов приложения, а не системная песочница**. Пути файлов проверяются после разрешения симлинков; shell-команда после подтверждения имеет обычные права процесса, в том числе сетевой доступ. Для изоляции недоверенного кода запускай Puppy в отдельном контейнере/аккаунте. Конкурентная подмена путей другим процессом не защищена на уровне ОС. Ключи настроенных API-провайдеров убираются из окружения shell-инструмента; другие переменные окружения наследуются.

## Контекст, память и инструкции

- SQLite хранит сообщения пользователя, ответы, вызовы инструментов, результаты, рабочую директорию, дерево агентов, права, расход токенов и события. Файлы БД лежат в `dataDir`, отдельно от tmp.
- Сообщение модели сохраняется **до** выполнения инструментов. Каждый результат фиксируется отдельно. При восстановлении незавершённый вызов получает отметку «исход неизвестен»; Puppy не повторяет его автоматически.
- Долгие беседы сжимаются в резюме по консервативной оценке размера; полный исходный журнал остаётся в SQL. Недавние пользовательские ходы сохраняются целиком. Внутри одной длинной задачи можно сжать старые циклы инструментов, сохранив точный исходный запрос пользователя и два последних полных цикла ответов. Вызовы инструментов не разрываются с результатами. Если сам запрос или последние данные слишком велики, Puppy останавливается с объяснением вместо тихого удаления сообщений. `contextBudgetTokens` настраивай ниже окна выбранной модели; это оценка, а не точный токенизатор.
- Память имеет области `global`, `project:<workspace>` и `session:<id>`. Инструмент `remember` пишет только в проектную/сессионную область с проверкой прав. Память загружается в системный контекст перед каждым запросом. Дочерний агент получает общую память проекта и отдельную сессионную память.
- Общие инструкции задаются в `instructions` и `instructionFiles` (абсолютные пути или `~/...`). В проекте автоматически читаются `AGENTS.md` и `.puppy/AGENTS.md` от корня рабочей области до текущей директории. При обращении к файлу во вложенном каталоге новые инструкции возвращаются модели **до** чтения/изменения файла с просьбой повторить вызов после их учёта. Команды shell должны самостоятельно соблюдать область инструкций.
- События запросов сохраняют снимок системных инструкций и ID сообщений для воспроизводимости. Не помещай секреты в инструкции, память и запросы; они попадают в локальную историю и отправляются выбранному API-провайдеру.

## Расходы, кэш и лимиты

Каждый API-запрос получает запись в SQL **до отправки**: ID задачи и сессии, провайдер, запрошенная и фактическая модель, ID ответа, время, статус, исходные счётчики и снимок настроенных тарифов. Отдельно видны успешные ответы, ошибки потоков и запросы с неизвестным исходом после прерывания. Запросы сжатия контекста тоже учитываются.

Обычный ввод, чтение кэша, создание кэша, записи на 5 минут/1 час и вывод считаются раздельно. В Anthropic кэш не входит в `input_tokens`, а в OpenAI cached-токены уже входят в `prompt_tokens`; Puppy не складывает их дважды. Отсутствующие поля остаются `null`, отчёт показывает, для скольких запросов есть данные.

`credits_consumed` сохраняется как **списание конкретного запроса по данным Kie**. Разница баланса аккаунта не приписывается запросу. Если поле отсутствует, стоимость неизвестна. Оценка USD по токенам и пересчёт кредитов в USD — отдельные показатели, которые используют только настроенный `pricing` и сохраняют снимок тарифов. Тарифы Kie на кэш не предполагаются; фиксированный процент экономии не обещается.

Если streaming провайдера не возвращает списание, задача под лимитом остановится. Проверь запрос в логах провайдера и для новой задачи выбери `stream: false`, если обычные ответы возвращают кредиты. Puppy не повторит платный запрос автоматически ради получения стоимости.

```bash
npm start -- usage --json
npm start -- usage SESSION_ID --run-id TASK_ID --json
```

Выгрузка включает родителя и всех щенков. Для сравнения с Cursor используй одинаковые задачи и состояние репозитория, разделяй запуски по ID задачи. Сумма времени API-запросов не равна времени всей задачи: параллельные запросы перекрываются. Успешный статус агента не является независимой оценкой правильности результата.

В настройках Kie по умолчанию стоит `maxTaskCredits: 10`. Измени положительное значение для новых задач или убери поле, чтобы отключить порог кредитов. Родитель, щенки и сжатие контекста тратят общий бюджет задачи. `/continue` сохраняет расход и порог незавершённой задачи; новая пользовательская задача получает новый бюджет. Число уже выполненных API-запросов также учитывается при продолжении.

После достижения порога новые модельные запросы не отправляются; ожидающие вызовы инструментов из этого ответа не исполняются. При неизвестном списании ограниченная по кредитам задача тоже останавливается. **Это порог остановки, а не гарантированный потолок списания:** один запрос или несколько уже отправленных параллельных запросов могут превысить остаток. Провайдер не сообщает заранее верхнюю цену. Другие приложения и произвольные shell-команды в этот журнал не входят. Запрос, прерванный аварийным выходом, остаётся с неизвестным списанием и блокирует продолжение под лимитом до проверки; новая задача — это явное выделение нового бюджета.

`promptCache: "off" | "5m" | "1h"` управляет автоматическим `cache_control` Anthropic-протокола. Для Kie по умолчанию `off`, пока поддержка директив и тарификация не проверены на твоём аккаунте; возвращаемая статистика кэша всё равно записывается. Пример прямого Anthropic API включает 5-минутный кэш и датированный редактируемый снимок официальных тарифов. [Документация Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

## Щенки-помощники

Инструменты `spawn_puppy`, `wait_puppies`, `list_puppies` позволяют модели запускать независимые задачи. У каждого щенка своя SQL-сессия, родительский ID, контекст и сохранённый результат. Дочерний щенок наследует модель, провайдера, рабочую область и права родителя; получает резюме и ограниченный снимок последнего контекста. Полная родительская переписка остаётся в SQL.

`maxChildren` ограничивает общее количество помощников за один запуск задачи, `maxParallelChildren` — одновременно работающих, `maxDepth` — вложенность. `maxPackCalls` ограничивает **общие** API-вызовы всей стаи, включая сжатие контекста; `maxSteps` ограничивает каждый агент. При заполненной стае новый spawn отклоняется: нужно дождаться существующих помощников. Родитель может продолжать работать параллельно. Директория общая — задачи с записью нужно разделять по файлам. Автоматического merge и изолированных worktree пока нет.

После восстановления родительской сессии `list_puppies` и `wait_puppies` показывают сохранённые отчёты помощников. Щенки, оставшиеся в состоянии работы без активной блокировки сессии, помечаются прерванными; автоматического перезапуска нет. Последний ответ прерванного щенка может быть неполным.

## Временные файлы

Задай `PUPPY_TMP_DIR` в `.env` самого Puppy: этот путь используется при `init` и последующих запусках без `--tmp`. Приоритет: явный `--tmp`, затем `PUPPY_TMP_DIR`, затем `tmpDir` из настроек. Изменение `.env` применяется при следующем запуске, включая восстановленные сессии. При инициализации выбранный путь сохраняется в конфигурации.

`tmpDir` обязателен, автоматической подмены системным temp нет. При запуске создаётся отдельный `run-UUID`; в него направлены `TMPDIR`, `TMP`, `TEMP`, npm cache, XDG cache и Python bytecode. Недоступный том `/Volumes/<name>` вызывает ошибку. Временная папка запуска удаляется при штатном выходе; после `SIGKILL` её можно удалить вручную. Постоянная SQLite-база сохраняется. Инструменты сборки, игнорирующие окружение, требуют явных путей вывода в командах; приложение не может принудительно перенаправить произвольную shell-программу без ОС-песочницы.

## Проверки

```bash
npm install
npm run typecheck
PUPPY_TEST_TMP=/absolute/test/temp npm test
```

Runtime использует только встроенные модули Node. TypeScript и `@types/node` нужны для статической проверки. Тесты с дисковыми артефактами требуют `PUPPY_TEST_TMP` и убирают свои каталоги. API-тесты используют локальные заглушки без ключей и списаний. Живой Kie-запрос требует твоего ключа и доступной модели.

OpenAI Chat пока возвращает ответы целиком. GUI, MCP, браузер, фоновое восстановление процессов после закрытия приложения и гарантированный провайдером денежный потолок пока не реализованы. HTTP-запросы не повторяются автоматически, чтобы не скрывать ошибки и повторные списания.


### Модели и настройки запуска

Основной движок — Claude Opus. Kie также возвращает `claude-fable-5`: выбор через `/model claude-fable-5`. Щенки наследуют модель, права и общий бюджет родителя. Для одновременной работы сначала запускаются независимые щенки, затем вызывается ожидание; `maxParallelChildren` по умолчанию равен 3.

```dotenv
PUPPY_PROVIDER=kie
PUPPY_MODEL=claude-opus-5-5
PUPPY_FALLBACK_MODEL=claude-sonnet-5-5
PUPPY_EFFORT=auto
PUPPY_MEMORY=true
PUPPY_FUNCTION_CALLING=true
PUPPY_MAX_TOKENS=4096
PUPPY_STREAM=true
```

Memory управляет отправкой предыдущих задач: SQL-история остаётся целой, а текущие вызовы инструментов сохраняются в контексте всегда. Function calling включает инструменты и щенков. Max tokens ограничивает каждый ответ модели. После изменения модели в `.env` запускай `puppy chat --new` или меняй `/model` в восстановленной сессии: у неё сохранён собственный выбор.

Для `gemini-4-carbon-openai` автоматически выбирается отдельный OpenAI endpoint Kie. Этот маршрут документирован как чатовый: инструменты и щенки для него отключены. Claude использует native Messages API с объединением соседних пользовательских сообщений и результатов инструментов для совместимости шлюза.

Для локальных Qwen/Llama запусти Ollama или LM Studio с моделью, поддерживающей инструменты. Задай `PUPPY_PROVIDER=ollama` (или `lmstudio`), `PUPPY_MODEL=<id установленной модели>`, `PUPPY_EFFORT=auto`. `/provider ollama` создаёт отдельную сессию и запрашивает установленные модели. Адреса по умолчанию: `http://127.0.0.1:11434/v1` и `http://127.0.0.1:1234/v1`; замена через `PUPPY_BASE_URL`. Для реального локального запроса сервер должен быть запущен.

Запасная модель — **Claude Sonnet 5.5**. `/fallback` проверяет её наличие у провайдера и переключает текущую сессию, сохраняя историю, права и бюджет. Настройка: `PUPPY_FALLBACK_MODEL` в `.env` или `fallbackModel` в профиле провайдера. Автоматического повтора платного запроса при ошибке нет; неизвестное списание продолжает блокировать `/continue`.
